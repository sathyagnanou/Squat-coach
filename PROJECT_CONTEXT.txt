1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
- Name: Squat Coach (IML2026 class project)
- Framework: Marcelle (https://marcelle.dev) — interactive ML toolkit
- Stack: JavaScript, Svelte, Vite
-   Scenario (teacher feedback): Focus on movement quality; a coach configures the
  system for athletes who need feedback on squat form (labels: good, knees_in,
  shallow — 3-label classification). The model is personalized (trained on user/coach data),
  not a pre-trained generic classifier.

3. MAIN APP (src/index.js) — IMPLEMENTED FEATURES
--------------------------------------------------------------------------------

3.1 Store & polyfill
- Uses marcelle.dataStore(storeUrl) with VITE_DATA_STORE_URL or course backend
- Array.prototype.toArray polyfill so Marcelle's internal .map(...).toArray()
  works when we pass plain arrays to classifier.train()

3.2 Datasets
- trainingSet = marcelle.dataset('project-images', store)   — user-recorded reps
- testSet    = marcelle.dataset('project-test-images', store) — curated test set

3.3 Inputs
- webcam = marcelle.webcam({ width: 224, height: 224 })
- upload = marcelle.imageUpload({ width: 224, height: 224 })
- lastWebcamImage, lastUploaded — kept via $images subscriptions

3.4 Model
- featureExtractor = marcelle.mobileNet()
- classifier = marcelle.mlpClassifier({ layers: [32, 32], epochs: 20 })
  .sync(store, 'mlp-squat-${team}')
- Transfer learning: MobileNet → MLP classifier

3.5 Labeling & data collection
- classLabels = ['good', 'knees_in', 'shallow']
- labelBar component — selects which label to use
- saveExampleToTraining(label) — saves webcam or upload to trainingSet
- saveExampleToTest(label) — saves upload to testSet (for curated Google images)
- Instance names: good_1, good_2, knees_in_1, etc. via nextName() and labelCounts

3.6 Buttons
- "Capture 1 instance (selected label)" → trainingSet
- "Add uploaded image to TEST (selected label)" → testSet
- "Start recording (every 0.5s)" / "Click to stop recording" — toggle, 500ms interval
- "Train model" — trains classifier on trainingSet (fetches items via .items().toArray())
- "Evaluate on TEST set" — runs model on testSet, computes accuracy + confusion matrix

3.7 Evaluation
- evalResultsStore (Svelte writable) holds { status, accuracy, perClass, confusion }
- evalResultsComp displays results in UI (idle / loading / done / error)
- Per-class accuracy and confusion matrix shown in "Evaluation results" panel

3.8 Dashboard pages
- Data Management: webcam, featureExtractor, upload, labelsUI, captureOneBtn,
  recordBtn, addToTestBtn, trainingBrowser
- Training: trainBtn, prog (trainingProgress)
- Real-time Prediction: webcam, predViz (confidencePlot)
- Performance: evalBtn, evalResultsComp, trainingBrowser, testBrowser

--------------------------------------------------------------------------------
4. KNOWN LIMITATIONS / DESIGN CHOICES
--------------------------------------------------------------------------------
- imageUpload: single image at a time; bulk upload via "Upload multiple images"
  button (file input with multiple) — all selected images added to training set
  with the currently selected label; test set typically prepared in advance.
- datasetBrowser displays actual image thumbnails when `thumbnail` is stored
  with each instance (new captures include thumbnails); custom instance names
  (good_1, etc.) are stored but may not be displayed in the browser.
- repReviewer component exists but is NOT wired — would need queueSet dataset
  and pipeline that pushes predictions + uncertainty into that queue.
- trainingSet.items().toArray() — used for training; may differ across Marcelle
  versions; polyfill ensures arrays work with classifier.train().
